git-dupe is a simple helper for Windows that gives your personal files their own history. Your notes, scripts, skills, and agent instructions stay versioned and safe, while staying completely hidden from the project's shared Git history. Think of it as a private notebook inside a shared work folder.

🚀 Getting Started

You do not need to be a programmer to use git-dupe. You only need a Windows computer and a folder where you keep personal files. git-dupe worksbest when you keep the files you want to protect inside a folder that also contains a project. git-dupe handles two separate histories at once, so there is no confusion and no accidental mixing.

Before you begin, make sure you have a Windows account with permission to create folders in your Documents area. That is all that is required.

✨ What git-dupe Does For You

Most version control tools are designed for the shared project. git-dupe was designed for everything that belongs to you. It keeps your own material in its own private history while the project folder stays clean.

  • Separate history for your files. Your notes and scripts get their own timeline of changes, completely independent from the project's history.
  • Hidden from the project. The project's Git never sees your private files, so they cannot show up in a shared commit by accident.
  • Works with folders you already have. There is no new format to learn and nothing to convert. Your files stay exactly where they are.
  • Great for agent instructions and skills. Keep the prompts and instruction files that power your AI helpers versioned and safe.
  • Cross-platform by design. Built to behave the same on Windows, macOS, and Linux, so your private setup travels with you.

🧭 Your First Five Minutes

You do not need to learn any commands. Follow these plain steps in order.

  1. Pick a folder. Choose the folder on your computer where you keep your notes, scripts, or agent instructions. If you do not have one yet, create a new folder in your Documents area and give it a clear name.
  2. Point git-dupe at it. Open git-dupe and select that folder when asked. The app will remember it for next time.
  3. Let it prepare the folder. git-dupe sets up a private history for your material. This happens once and takes only a moment.
  4. Keep working normally. Edit your files the way you always do. git-dupe tracks the changes in the background so you can go back to an earlier version whenever you need to.
  5. Check your history. Open the app whenever you want to see what changed and when. Each change is listed with a date and a short description.

💡 Good Habits That Save Time

  • Save a checkpoint before big edits. Before you rewrite an instruction file or restructure your notes, record a snapshot. Going back is much easier than retyping.
  • Write short descriptions. A few words like "updated skill list" make your history readable months later.
  • Keep private things private. Store passwords and secrets somewhere designed for them. git-dupe protects your files from the shared project, not from anyone looking at your own screen.
  • Let the project stay clean. If a file does not belong to the shared project, it belongs to git-dupe.

❓ Common Questions

Do I need to know Git?
No. git-dupe runs on top of Git for reliability, but every action is a plain choice in the app.

Will my private files appear in the shared project?
No. That is the whole point. The project's history never sees them.

Can I stop using it later?
Yes. Your files are ordinary files on your computer. Removing the app does not remove your notes.

Does it work outside of Windows?
Yes. The same approach is used on macOS and Linux, though these instructions cover Windows only.

What if I move my folder?
Open git-dupe and point it at the new location. Your history moves with the folder.

🛠️ If Something Goes Wrong

The app does not open. Close the message window and open the file again. If Windows asks for permission, allow it.

The folder is not recognised. Make sure you chose the folder itself, not a file inside it, and that the folder name has no unusual symbols.

You cannot see recent changes. Save your files in the app you were editing, then reopen git-dupe. The list refreshes each time it starts.

You want to start over. Choose a fresh folder and point git-dupe at it. Nothing in your old folder is deleted.
